# SiteForge ERP v28 — UX, Accessibility, i18n/RTL & Mobile Audit

**Repo:** `github.com/hamedalkitbi/Forgesite` @ `61ef1cb` ("installable PWA shell, zero-dependency test suite, CI and Pages workflows") · **Scope:** `index.html` (101 lines / 5,804 B), `styles/main.css` (245 lines / 22,444 B), `scripts/app.js` (3,135 lines / 256,537 B) · **Method:** full static read of all three files; WCAG 2.x contrast computed from sRGB relative luminance; no authenticated session available (login has no credentials), so flows were traced in source only. No repo file was modified; this report is the only write.

> **Note on revision:** the task cited `43be218`; the clone moved one commit forward *during* this audit (to `61ef1cb`). `styles/main.css` is byte-identical between the two, so all contrast numbers stand; `scripts/app.js` only gained an append-only test hook at EOF (old lines ≤ 3116 unchanged, so every `app.js:NNN` below is valid); `index.html` changed the most (PWA head, `noscript`, service-worker registration) — **all `index.html` line numbers below are verified against `61ef1cb`.**

## Summary

The SPA is visually polished and has real engineering discipline in places (129-key EN/AR parity, `t()` used at 543 call sites, print stylesheet with popup fallback, double-submit guards on the login and form modals, and a new PWA shell with `noscript` fallback). But it is a **keyboard- and screen-reader-hostile app**: the primary sidebar navigation is a set of `<div onclick>` rows (`nb()` call sites at `app.js:505`; up to 16 rendered at once) that cannot receive focus, every modal opens without moving focus (while claiming `aria-modal="true"`), all generated form labels are unassociated, and there is not a single `aria-live`, `aria-expanded`, `aria-current`, `aria-describedby` or `tabindex` in the codebase (verified: 3 `aria-*` attributes total, 0 `tabindex`, 0 `:focus-visible`, 0 `scope`/`<caption>`, 8 of 10 `<img>` without `alt`). RTL support is half-built — `dir`/`lang` **are** set at boot (`app.js:2493` via `3090`) and ~10 `html[dir="rtl"]` rules exist, but two of them double-flip `flex-direction` and the light theme systematically fails contrast (accent text 2.10–2.33:1, muted 3.95–4.40:1, `AED` pill 1.29:1). Mobile has a working drawer/backdrop and mostly-scrollwrapped tables, but tap targets and a 280px fixed-width settings form break at 320px. i18n is ~30% incomplete in generated markup (234 hardcoded English text nodes, 14 hardcoded modal titles, 33 hardcoded toasts, all 18 `confirm()` prompts, all dates/amounts forced to `en-US`). The new `tools/run-tests.mjs` contains an "Accessibility basics" block that checks only `html[lang]`, login-input labels and the dialog role — it computes an `unlabeledButtons` count and then **never asserts it** (and emoji-only buttons would pass anyway), so CI gives false confidence on exactly the areas that are broken.

**Tally:** 2 × P0, 8 × P1, 17 × P2, 2 × P3.

## Top 5 — recommended order

1. **Make the sidebar navigable (#1).** Single highest-value change: ~10 lines, no behaviour risk, unlocks all 25 views for keyboard/AT users. In `renderSidebar()`:
   ```js
   function nb(id,ic,l,bd){return '<button type="button" class="navitem'+(currentView===id?' on':'')+'"'
     +(currentView===id?' aria-current="page"':'')
     +' onclick="goView(\''+id+'\')"><span class="ic" aria-hidden="true">'+ic+'</span>'+l+(bd||'')+'</button>';}
   ```
   CSS: `.navitem{width:100%;text-align:start;background:none;border:1px solid transparent;font:inherit}` and `.navitem:focus-visible{outline:2px solid var(--accent-ink,#ff8c1a);outline-offset:-2px}`. Also add `aria-hidden="true"` to decorative emoji (`.ic`) so names aren't read as "picture frame".

2. **Give the dialog real focus behaviour (#2).** In `openModal()`: `_prevFocus=document.activeElement`, `<h3 id="modalTitle">`, `#modalRoot` → `aria-labelledby="modalTitle"`; after `innerHTML=`, `setTimeout(()=>{const f=r.querySelector('.mbody input,.mbody select,.mbody textarea')||r.querySelector('.mhead h3');f.tabIndex=-1;f.focus()},30)`. Add a `keydown` trap on the document (Tab/Shift+Tab wrap within `.mbox`) and in `closeModal()` `_prevFocus&&_prevFocus.focus()`. Extend the existing Escape handler (`app.js:3109`) to call `closeModal()` then restore focus.

3. **Name every control and announce every message (#3, #4).** Add `aria-label` to the icon-only button patterns in #3 (`☰`→"Menu", `🔔`→"Notifications", `🛡️`→"Approvals", `✕`→"Delete/Reject", `✎`→"Edit", `🖨`→"Print", `✓`→"Approve"). Then make feedback perceivable: `#loginError` and `.ferror` get `role="alert"`, and render toasts into one persistent `<div id="toasts" role="status" aria-live="polite">` instead of `document.body.appendChild` so successive messages are announced.

4. **Associate labels and errors (#5).** `buildForm()` is the single choke point for ~45 inputs: `<label for="f_'+f.key+'">`, `aria-required` when `f.required`, and on `readForm()` failure set `#formErr` to `role="alert"` + focus the first invalid `#f_*`. Also add `for=` to the 24 inline `<label>`s (settings, branding, rejection reason, password change, expense scan fields).

5. **Fix the theme tokens and the two double-flips (#7, #8, #9, #14–#17).** One CSS pass:
   ```css
   html[data-theme="light"]{--muted:#57606a;--accent-ink:#a34e00}
   html[data-theme="light"] .pill.aed{color:#8a4700}
   .btn.bad{background:var(--bad);color:#2a0d0a}   /* 5.9:1 dark */
   :focus-visible{outline:2px solid var(--accent-ink,var(--accent));outline-offset:2px}
   /* delete html[dir="rtl"] .shell{flex-direction:row-reverse} and .mfoot{flex-direction:row-reverse} */
   .sidebar{border-inline-end:1px solid var(--line)}
   ```
   Because `applySettings()` writes `--accent` as an inline style on `<html>`, text colours in light theme must use a separate `--accent-ink` token (or darken `--accent` in JS when `theme==='light'`).

## Verification notes (baseline checked, not assumed)

- **`dir`/`lang` ARE set.** `applySettings()` (`app.js:2493`) sets `data-theme`, `data-font`, `dir`, `lang`, `--accent`, `--fs`, and is called at boot (`app.js:3090`), so RTL applies before login without visiting Settings. CSS has `html[dir="rtl"]` rules at `main.css:77-78, 84, 104, 110, 142, 145, 173, 222, 224`. The defects are the two double-flips (#16, #17) and the physical properties (#28), not a missing mechanism.
- **ARIA baseline confirmed on the current tree:** 3 attributes total — `aria-label` ×2 (`app.js:608, 2692`), `aria-modal` ×1 (`index.html:84`); 0 `tabindex`, 0 `aria-live/expanded/current/controls/describedby/invalid/required/labelledby`, 0 `role=` except the dialog, 0 `:focus-visible`, 0 `scope`, 0 `<caption>`, 0 skip link. Only keyboard handler is `document.addEventListener('keydown', ... Escape ...)` at `app.js:3109-3112`.
- **i18n:** `LANG.en` and `LANG.ar` both have 129 keys with full parity; `t()` is used 543 times across 126 distinct keys; but 234 hardcoded English text nodes, 14 hardcoded `openModal` titles, 33 hardcoded `toast('…')` calls, 18 `confirm()` prompts and 48 direct `textContent='…'` error strings remain hardcoded.
- **Login is the good citizen:** labels use `for=` (`index.html:41, 45, 49`), submit is double-submit-guarded (`app.js:120-124`), the form modal has a `_submitting` guard (`app.js:678-690`), approvals batch has `_batchBusy` (`app.js:2788`).
- **Responsive login is fine:** `.login-stage` collapses 1.05fr/.95fr → `1fr` at ≤800px with aside `min-height:0` (`main.css:46-52`). Viewport now has `viewport-fit=cover` and `color-scheme` (`index.html:5, 8`) and zoom is allowed (good), **but** CSS still consumes no safe-area insets (0 `env(safe-area-inset-*)`), so `.topbar` and the fixed `.app-dock` sit under the iOS notch/home indicator.
- **Table overflow:** 20 of 28 tables are wrapped in `overflow-x:auto` divs; the Users table (`app.js:2560`) is the notable unwrapped one. `th{white-space:nowrap}` (`main.css:103`) is what makes widths large.
- **Print:** print stylesheet hides chrome and shows `.print-header`/`.print-signatures` (`main.css:201-213`); `openPrintDoc()` writes into a new window and falls back to `#printSheet` if popups are blocked (`app.js:2244-2258`). Print documents are LTR/English/Arial with no `dir` and no Arabic font fallback.
- **New PWA shell (this revision):** `sw.js` + `site.webmanifest` + icons + `noscript` fallback (`index.html:87-99`) are a genuine improvement for resilience; manifest declares `"lang":"en","dir":"auto"`, so an installed app cannot follow the in-app Arabic language (minor i18n gap, not ranked).
- **Existing tests give false confidence:** `tools/run-tests.mjs:230-248` ("Accessibility basics") asserts only `html[lang]`, `#loginScreen` input labels and `role="dialog"`. It computes `unlabeledButtons` (`run-tests.mjs:238`) but never asserts it — and because it filters on `b.textContent.trim()`, emoji-only buttons (`🔔`, `✕`, `✎`) would pass anyway.
