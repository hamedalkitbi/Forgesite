# Data Layer & Business-Logic Correctness Audit — Forgesite `scripts/app.js`

**Baseline:** git `43be218` (the worktree later advanced to `61ef1cb`, whose only `app.js` change is a 15-line append-only `?selftest=1` test surface at EOF — every line number below was re-verified against the current worktree and is unchanged). Read-only source audit; no live credentials, so anything depending on DB schema defaults, RLS policies or interleaving of real network calls is tagged **unverified**. No app file was modified.

**Summary.** The app's data layer is built around a small set of helpers (`fetchAllRows`, `insertRow`, `updateRow`, `deleteRow`, `logTransaction`) that are structurally failure-silent: `fetchAllRows` converts any query error into partial/empty data, `updateRow`'s optimistic-concurrency parameter exists but is never passed by any of its 22 call sites, and `logTransaction` neither checks the PostgREST `error` field nor is awaited by its callers, so a mutation can commit with no audit record and no warning. On top of that, `switchProject`/`loadProjectData` have no generation token or try/catch, so a failed or interleaved load leaves `state.currentProjectId` pointing at the new project while the project-scoped arrays still hold the previous project's rows — after which `newMaterial`/`newTimesheet`/`newPayment`/`submitScan` post the old project's data under the new `project_id` (ranked P0 because it misattributes financial records). The business math itself is mostly defensible (IPC retention/advance recovery is capped correctly, OT premium is 1.5×, BOQ budget vs. actuals is guarded against divide-by-zero), but the IPC chain clamps negative period deltas to zero and never recomputes dependent certificates, the approvals queue only ever sees the current project's cached rows and writes status without a `status='pending'` precondition (double-approval / conflicting decisions are possible), and material/BOQ linking via a 50-character truncated datalist label can silently attach a PO or timesheet to the wrong BOQ line. The findings below are all read directly from source; the four items requiring runtime/DB confirmation are marked in their Fix/Risk column.

## Top 5 — recommended order

1. **Make the load path fail loudly (#1, #2).** Add `state._loadGen`; in `switchProject`/`loadProjectData` capture `var pid` and `var gen=++state._loadGen`, wrap in `try/catch`, and after every `await` abort when `gen!==state._loadGen || state.currentProjectId!==pid`; on error reset `currentProjectId/currentProject` and clear project-scoped arrays. Change `fetchAllRows` to `return {rows,error}` (or throw) and have each loader only `mapProjectTable` on `.error===null`, else keep old state and show a retry toast. This removes both the wrong-project-write and the silent-zeroing class in one change.
2. **Wire the existing concurrency control (#3, #5).** Keep `updated_at` in `mapProjectTable` rows; pass `row.updatedAt` from every editor (`editBilling`, `editBOQ`, material/timesheet edit, `workerRow` edits) and add `.eq('status','pending')` (or an expected-status argument) to `updateRow` for `writeApproval`/`approveItem`. Make the update payload send only changed fields where practical so a stale editor can't rewrite unrelated money columns.
3. **Make mutation + audit atomic from the app's perspective (#4, #7, #11, #12).** `await logTransaction`, check `r.error`, and surface "saved, audit write failed"; add `.select('id')` + length check to `deleteRow`; throw on dropped critical columns instead of silently continuing; and split "save" from "reload" in `submitFormModal` so a refresh failure never prompts a duplicate insert.
4. **Close the approval-integrity gaps (#5, #6, #8, #9, #10).** Always write an explicit `status` on create paths (`commitScan`, bulk imports), treat `NULL` status as `pending` in `collectPendingItems`/`getBoqActualsMap`/dashboard filters, record `approved_by`/`rejected_by` per row, log only successful batch items and their exposure, and build the company-level queue from a real cross-project `status='pending'` query rather than per-project cache.
5. **Fix the two math/linking defects that corrupt reported cost (#14, #15, #18).** Pass ids (not 50-char labels) through the BOQ `searchable_select` so a PO/timesheet cannot attach to the wrong BOQ line; keep signed IPC deltas and recompute dependent certificates after create/edit/certify/delete; cap payroll loan deduction at `min(loan, netSalary)` and carry the shortfall forward.
