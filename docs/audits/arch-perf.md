# Forgesite — Architecture, Performance, Security-Posture & Tooling Audit

- **Repo:** `github.com/hamedalkitbi/Forgesite` (MIT). Audited tree: **HEAD `61ef1cb`** ("feat: installable PWA shell, zero-dependency test suite, CI and Pages workflows", 2026-11-03). The brief named `43be218`; a new commit landed mid-audit, so line references below are for `61ef1cb` and items that commit fixed are separated in §"Already fixed during the audit".
- **Scope:** architecture/load, memory/listeners, CDN supply chain, security posture (anon key, XSS/CSV, auth storage), PWA/offline, CI/tooling, maintainability.
- **Method:** file reads + grep/Python static counts over `scripts/app.js`, `index.html`, `styles/main.css`, `sw.js`, CI files; per-view render payloads measured by executing the app's real render functions in a Node sandbox against synthetic but realistic state (200 workers, 300 BOQ lines, 400 timesheets, 150 materials/expenses, 300 audit rows); load timings from headless Chrome 145 via CDP (cache disabled, localhost); ran `node tools/run-tests.mjs` (30/30 passed). No repo file was modified except this report.
- **Legend:** Effort S ≤ 2 h, M ≈ 1 day, L ≥ 3 days. Risk = risk of the fix itself.

## Summary

The app is a 256 KB single-IIFE SPA with no build, no modules and no tests of its own logic; every state change is a Supabase round-trip followed by `innerHTML` rebuild of the entire `#main` (plus topbar/sidebar). At realistic volumes a single re-render is 118–206 KB of HTML and 3.0k–7.0k elements (measured), which is fine at 300 rows and will visibly stutter at 1–2k rows. Static XSS hygiene is actually good — 315 `esc()` calls, `safeImgSrc`/`safeSpreadsheetCell` helpers, no unescaped free-text interpolation found in a full attribute/text sweep, no string-interpolated PostgREST filters, no open redirects — but 163 inline `onclick=` handlers and no CSP mean the first escaping slip is game-over, and the session token lives in `localStorage`. The anon key in source is **by design public**, so the entire authorization boundary is Postgres RLS; nothing in the repo defines or tests a policy, and one code path (`changeRole`) writes `profiles.role` straight from the browser instead of through the existing `adminOp` edge function. Largest remaining ROI: make authorization verifiable (RLS-as-code + CI denial tests), then stop re-rendering the world.

## Top 5 — recommended order

1. **Make authorization verifiable (P0, M).** Add `supabase/migrations/` with RLS policies for all 24 application tables + the `siteforge-files` bucket; add a CI job that signs in as (a) anon, (b) `lead`, (c) `super` and asserts denial on `profiles`, `payroll_batches`, `company_budget_lines`, and on `profiles.role` self-update. Route `changeRole` through the existing `adminOp` edge function. A green test is the only thing that turns "the anon key is public" from a risk into a documented property.
2. **Close the supply-chain/XSS surface (P1, S→L, split it).** Day 1: SRI hashes on the two `<head>` scripts + Tesseract, or vendor them (also fixes the 703 ms blocking xlsx load and gives offline reliability). Day 2: replace inline `onclick` with the `data-action` delegation already used at `app.js:3097`, then enable CSP (`script-src 'self'` + hashes; no `unsafe-inline`) — that is what makes `localStorage` session theft (#5) survivable.
3. **Stop re-rendering the world (P2, M).** Keep the static shell; re-render only `#main` on view change and only `<tbody>` rows after a mutation. Add a 150 ms debounce to the two search inputs, paginate history/expenses (100 + "load more"), row-window above ~300 rows. Expected: BOQ/Timesheets/Compliance re-renders drop from the measured 118–206 KB / 3–7k elements to <10 KB for a one-row change.
4. **Make failure visible and recoverable (P1, S).** Dismissible/auto-hiding error banner, `unhandledrejection` handler, `fetchJson` with `AbortController` timeouts (5 call sites), and an explicit offline state that disables submit buttons instead of implying queued writes.
5. **Introduce three seams + lint them (P2, L).** `data.js` (queries/mappers/`mutate()`), `ui.js` (`esc`/row/table builders + delegated actions), `print.js` (one print document builder + reused window). Classic scripts on a single `window.SF` namespace — no framework, no bundler required (esbuild optional later). Add ESLint (`no-undef`, `no-unused-vars`, `no-eval`) so the seams stay sealed.

## Appendix B — checks that came back clean (kept to avoid redundant fixes)

- **Listener/timer leaks: none found.** Only 9 `addEventListener` calls total — 5 global (`DOMContentLoaded`, `click`, `keydown`, `offline`, `online`), 4 scoped to elements created in modals/settings (`app.js:1406`, `:1940-1941`, `:3094`). No `setInterval`, no per-render global handlers; re-created elements take their listeners with them. The real leak is print popups (#12) and the 129 `window.*` handles/bound globals.
- **No PostgREST/SQL-injection-style filter interpolation.** Queries use `.eq/.in/.range/.order` with values and a fixed table list; there is no user-controlled `.or()`/`.filter()` string. The only raw REST URL is `profiles?id=eq.` + `encodeURIComponent(...)` (`app.js:132`), which is safe.
- **No open redirect.** No `location.href/replace/assign` or `redirectTo` anywhere; signed-URL `window.open` calls pass `noopener,noreferrer` (`:1288`, `:1869`).
- **CSV/formula injection is covered.** Only two exporters exist (`exportHistoryCsv:2877`, `exportBOQExcel:3061`), and both wrap every string cell in `safeSpreadsheetCell` (leading `=+-@` prefixed with `'`); numeric cells stay numeric. UTF-8 BOM added on CSV.
- **Print documents escape user data.** Invoice/IPC/expense/payslip builders consistently `esc()` free text and use `safeImgSrc` for logos; the unescaped interpolation sweep over all HTML lines returned only static labels.
- **No secret beyond the by-design anon key.** The committed JWT has `role:"anon"` (not `service_role`), expires 2036-10-18; no other credentials/keys in the tree. `Remember me` stores only the username (`saveRemembered`, `:107`).
- **Untrusted free-text into `innerHTML`:** a regex sweep for known free-text fields (`name/desc/notes/title/reason/address/phone/email/...`) interpolated into HTML without `esc()` returned 3 hits, all false positives (static form labels, already-esc'd expressions).

## Appendix C — limits of this audit

- No login credentials, so runtime cost was measured by executing the real render functions over synthetic state rather than against the live Supabase project; RLS was reasoned about, not probed (deliberately — no production probing).
- CDP/Chrome on port 9222 died mid-session; load timings come from one cold-cache localhost run (DCL 780 ms / FCP 800 ms) and are indicative, not a lab benchmark. The local dev server sends no gzip; production hosts will compress `app.js` to ~61 KB.
- Line numbers are for `61ef1cb`; for `43be218` the `index.html` refs are offset by −10 lines after line 8 (e.g. CDN scripts at 8-9, `#version` at 14, `app.js` at 76).
